P 端在线 W8A8：shared expert 与 attention 的 q_b_proj / o_proj

2026-11-16 量化 W8A8 FP8 prefill MoE shared expert

P 端有两处 GEMM 吃掉了不少时间，而它们的权重在 checkpoint 里还是 BF16。在线量化的做法是：加载时把权重量化成 FP8，运行期再把激活动态量化 —— checkpoint 本身一个字节都不改。两个落点（shared expert、attention 的 q_b_proj / o_proj）收益都不大，但它们回答了一个反复被问的问题：「量化为什么不能一次做在 checkpoint 里？」因为有些权重你不敢离线量化，只敢在线试。

速览 「在线」是什么意思 两个落点在哪 收益账 只在 P 开、只在 TP≤4 缺口 常见误解 自测

术语约定：W8A8 = 权重 8 bit、激活 8 bit；checkpoint、online、dynamic、GEMM、P / D 保留英文。本文讲的是四机 PD 线 P 端（tp=4 / pp=4 / cp=4）的两处在线量化；同一套思路在别处（KV、通信）上的用法不在本页。

01速览

TL;DR

  • 「在线」= 加载时量化权重 + 运行期动态量化激活。 checkpoint 仍是 BF16，随时可以关掉回到原精度 —— 这是它相对「改 checkpoint」的全部价值。
  • 两个落点：shared expert 与 attention 的两个投影。 前者在 MoE 里那份「所有 token 都要过」的稠密专家上；后者是 q_b_proj / o_proj。
  • 收益很小，但链条是干净的。 quant-RS 之后做顺序对照：一次 prefill_forward 8.05 → 7.83 s；196K/384 的 TTFT 8679 → 8463 ms。
  • 只能 P 开。 D 侧同类开关一律 0；attention 那两个投影还额外要求 TP≤4。
  • 最大缺口是质量证据。 没有全模型困惑度对比；而且 attention 那组数字是「release + port」的组合，不能整份归给两个投影。

02「在线」是什么意思，以及它换来了什么

「离线量化」是改 checkpoint：把 BF16 权重换成 FP8 存下来，上线直接加载。「在线量化」不动 checkpoint，是在权重加载之后、跑起来之前做一次转换，并给激活挂一个动态量化钩子。

// 形状差别（伪代码，不是源码）
// 离线：改 checkpoint，省显存也省带宽，但改不回来
weight_fp8 = quantize(checkpoint_bf16); save(weight_fp8)

// 在线：checkpoint 原样，转换发生在加载之后
weight = load(checkpoint_bf16)                  // 磁盘上还是 BF16
weight = quantize_at_load(weight)             // 加载时转一次
out    = gemm(weight, dynamic_quant(x))         // 激活每次前向现量

它换来的不是「更强的量化」，而是三件事：①试验成本低（改一个开关，改不回来就关掉）；②不用重新分发权重；③可以只对某几个 GEMM 开。代价也很清楚：转换发生在每次加载，而且激活是动态量化的，误差不可预先标定。

两处的分量不同：shared expert 是每个 token 都要过的那份稠密专家，所以它对 prefill 的贡献随 token 数线性增长；attention 的两个投影则是 TP≤4 时每卡都要做的 [tokens × hidden] × [hidden × …] 矩阵乘。它们都不在「已经 4 bit 的 routed expert」上 —— 这也是为什么收益只能是个位数：大头早就被权重格式本身吃掉了。

06缺口：没有全模型困惑度对比

  • checkpoint 保 BF16，但运行时数值变了。 权重在加载时被量化、激活每次前向现量 —— 这不是「精度无损」的优化，只是「随时可关」。
  • 没有全模型困惑度对比。 现有质量证据是组合级的 7/7 门（与原精度对照的判定），不是逐项困惑度曲线。要把它当默认开启，这条缺口得补。
  • 动态量化的误差不可预先标定。 激活的 scale 随输入分布走，长输入与短输入的量化误差不一样；压测覆盖不到的输入分布，就没有对应的质量证据。

07常见误解

①「在线量化是为了省显存」

不是。它在加载时转换，峰值显存并不会因此少一份（转换过程中两份都在）。它买的是试验成本和可关性：改一个开关就能试，试不出来就关掉，不动 checkpoint。

②「routed expert 已经是 4 bit 了，再给别的层开 FP8 应该收益更大」

恰恰相反。routed expert 是权重的大头，早就被权重格式吃掉了；剩下这几处是「部分 token 才走」或「按 head 切分」的 GEMM，占比小。所以它们的收益只能是个位数。

③「P 端有效，D 端照着开就行」

不行。P 是算力受限，D 是访存受限：D 侧的关键是「少读权重」，而在线 W8A8 并不减少权重读取（转换发生在加载后，权重还是要在显存里）。

④「18.0 → 11.9 s 是这两个投影带来的」

不能这样归因。那个数字是 release + port 的组合结果，原始记录明确写了它含并行方式的改动。能单独归给两个投影的，只有「质量门 7/7」和「TP≤4 的定位」。

08自测

在线量化与离线量化的分界在哪一行代码？

在「权重从哪来」：离线量化改 checkpoint（存下来就是 FP8），在线量化 checkpoint 仍是 BF16、在加载之后转一次，并给激活挂动态量化。判断标准是「磁盘上那份是不是原精度」。

为什么 shared expert 值得动，而 dense FFN 不值得？

shared expert 每个 token 都要过，prefill 的收益随 token 数线性增长；而同类改动在 dense FFN 上实测是中性 —— 没有收益却要付同样的数值风险，所以不扩。

8.40 → 7.83 s 这个链条为什么只能顺序读？

因为是叠加测量的：每一步的基准都是上一步的结果。想看单项就只能看相邻两行，不能把两段减量当成「各自相对原始基准」的收益。

这套改动最大的证据缺口是什么？

没有全模型困惑度对比。现有质量证据是组合级的通过/不通过，不是逐项曲线；而且动态量化的误差随输入分布变化，压测覆盖不到的部分没有证据。

为什么 attention 那两个投影要限定 TP≤4？

因为它的收益来自「每卡 GEMM 的占比」；TP 越大，每卡的矩阵越窄，量子化的固定成本（转换、scale）摊到更少的计算上，收益就不再成立。原始记录也明确把它定位成 TP≤4 的 performance piece。
