SGLang 的 LayerSplit：把 DSA 的 KV/indexer cache 按层摊到 prefill CP 的各 rank

2026-11-16 SGLang v0.5.23 DSA · PD · CP 读源码

SGLang 里叫 layer split 的东西只有一个：--enable-dsa-cache-layer-split。 它不新增并行维度，也不改变任何一个 kernel 的计算形状 —— 它只挪动一件事：第 l 层的 KV 落在哪张卡上。 本页把这条机制从层归属公式、buffer 分配、owner 广播、PD 传输出口的顺序走一遍， 并把「它和 TP / PP / DP 到底什么关系」按源码里的实际约束说清楚。

TL;DR · 五条

  • 切的是 cache 的归属，不是计算。TP 宽度、CP 的 token 分配、请求到 rank 的映射全都不变； 变的只有「第 l 层的 KV 存在谁手里」。
  • 每 rank 只 materialize ceil(L/S) 层（S = attn_cp_size）， 外加 1 层 remote scratch；因此单卡 KV 从 L 层降到 ceil(L/S)+1 层。
  • 只有 PD 的 prefill worker 能开。必须 --disaggregation-mode prefill、 --enable-prefill-cp --cp-strategy interleave、--attn-cp-size > 1、 --pp-size 1、transfer backend 为 mooncake。
  • 非 owner 层的读 = owner 广播整层 buffer。广播的张量是整个 (size + page_size) 行， 不是本批次用到的 page —— 这是这条路径上最容易被低估的通信量。
  • 它买的是 prefill 侧的容量，不是单请求延迟。同显存下 token 容量约 ×S； 代价是每读一层远程层就要搬一整层。
术语约定
  • LayerSplit：本页只指 --enable-dsa-cache-layer-split 打开的那套机制。 它与 PP 帮助文本里那句 "the model is split by layer" 不是一回事 —— 后者切的是计算图， LayerSplit 切的是 KV cache 的归属，见 06 节。
  • rank / owner：CP 组内的序号与「拥有某层 KV 的 rank」；scratch：每个 rank 保留的那一份整层远程 buffer。
  • DSA（DeepSeek Sparse Attention）、MLA（multi-head latent attention）、 PD（prefill/decode 分离）、CP（context parallel）保持英文，因为它们在日志与参数名里就是英文。
  • 行号对应 v0.5.23；核心实现文件与本地 vendored snapshot 逐字节一致（见页脚）。

01它要解决的问题：MLA 的 KV 在 TP 组内是复制的

先把前提摆清楚，否则后面每一步都像在讲优化，其实是在讲一个不得不做的取舍。

SGLang 的 MLA 后端里，每个 TP rank 都持有完整的 KV cache —— 不是 1/TP。 多头潜在注意力把 K/V 压成一个共享的 latent（kv_lora_rank + qk_rope_head_dim）， 各 head 读同一份 latent，所以按 head 切没有意义，TP 只切权重与计算。 结论：加宽 TP 不会让 KV 变小，只会让算力变大。

DSA 模型在这之上还有一份 indexer 的 index-K cache，同样逐层、同样在 TP 组内复制。 prefill 侧要处理的是整段长上下文，KV + indexer 一起把显存吃满， 于是 max_total_num_tokens（也就是 radix cache 能装多少 token）被压下来， prefill 吞吐直接跟着掉。

LayerSplit 的做法很直接：既然 KV 是「层 × token × dim」的三维张量，而层这个维度在 TP 组内本来就一模一样， 那就把层按 CP rank 分掉。第 l 层的 KV 只由它的 owner 写， 别的 rank 要读就向 owner 广播一份到 scratch。复制变成了按层分持。

为什么必须挂在 CP 上，而不是 TP 上？ 因为分完之后每张卡都缺一部分层，读远程层必须有一次集合通信把整层搬过来。 CP 组本来就是「同一次前向里、处理同一批 token 的若干 rank」，天然是这次广播的合适作用域； 而且 PD 的传输侧本来就要按 CP rank 分片发。源码里广播组的选法就是 get_parallel().attn_cp_group （mem_cache/dsa_cache_layer_split.py:253-269）。

03机制：从层归属到广播，五步走完

3.1 层归属：连续、均衡、前 rem 个 rank 多一层

整个机制的地基是一个纯函数，没有任何通信：

get_layer_shard_range(rank, S, L):
  base  = L // S
  rem   = L %  S
  start = rank * base + min(rank, rem)
  end   = start + base + (1 if rank < rem else 0)
  return start, end

layers/cp/utils.py:97-106；get_layer_owner() 是它的反函数（:108-126）。

取 L = 10, S = 4，区间与归属是（单测里逐项断言过，test/registered/unit/mem_cache/test_dsa_layer_shard_utils.py:14-27）：

r0 → [0, 3)   r1 → [3, 6)   r2 → [6, 8)   r3 → [8, 10)
owner(layer 0..9) = [0,0,0, 1,1,1, 2,2, 3,3]

层 → owner 的分布（滑块在下方 05 节，改 L / S 这里会跟着变）

注意这个函数对「层数不能被 S 整除」是良定义的：L = 2, S = 4 时后面两个 rank 拿到空区间 [2, 2)，它们自己的 scratch 仍然存在，只是所有层都要广播。 get_layer_owner() 对空区间不会返回那个 rank，因为它的判据是 start <= i < end。

3.2 分配：owner 拿满，别人拿 0 行，另备一份 scratch

kv_buffer[i] = (size + page_size, 1, kv_dim)   if _is_layer_owned(start_layer + i)
             = (0,              1, kv_dim)     otherwise      # 0 行占位，保持层号对齐

remote_kv_buffer = (size + page_size, 1, kv_dim)                # 全 rank 各一份

dsa_cache_layer_split.py:306-343。

「0 行占位」这个细节值得停一下：它让 kv_buffer[layer_id - start_layer] 这个寻址方式完全不用改， 所有既有的按层遍历（move_kv_cache、HiCache 的 CPU offload、PD 的 buffer 上报）都能原样工作 —— 只是遇到 0 行的层直接 continue。

而 +1 这个 scratch 也进了显存账：KV 池的 cell size 是按 effective_num_layers = max(1, ceil(L/S) + 1) 算的（layers/cp/utils.py:76-95， 被 model_executor/pool_configurator.py:349 调用）。 所以「省了多少」的准确式子不是 1 - 1/S，而是：

单卡 KV 占比 = (ceil(L/S) + 1) / L，省下 1 - (ceil(L/S) + 1) / L。 GLM 的 cookbook 里写的「up to 75%」（docs/cookbook/autoregressive/GLM/GLM-5.2.mdx:337） 是忽略 scratch 的渐近值 1 - 1/S，在 S = 4 时等于 75%。 同一显存下 token 容量约涨到 L / (ceil(L/S) + 1) 倍。

3.3 写：只有 owner 落盘，写会作废远程副本

set_kv_buffer() / set_mla_kv_buffer() 在写完本 rank 的 buffer 之后， 若发现 remote_kv_layer_id == layer_id，就直接把它置 None（:395-420、:422-448）。 理由很朴素：scratch 里那份可能已经旧了，下次读必须重新广播。 同一个道理，indexer 侧有自己的 invalidate()（:129-132），靠 remote_layer_id 判断。

3.4 读：owner 广播进 scratch，且提前一层预取

读路径是这条机制里唯一有通信的地方：

get_key_buffer(l) / get_value_buffer(l)
  └─ _get_broadcastable_kv_buffer(l)                    # :507
       if remote_kv_layer_id == l: return remote_kv_buffer   # 命中，直接用
       src = kv_buffer[l] if _is_layer_owned(l) else None
       _broadcast_tensor_from_owner(remote_kv_buffer, l, src_tensor=src)   # :271
       remote_kv_layer_id = l
       return remote_kv_buffer

而 _broadcast_tensor_from_owner() 里那句 comm.broadcast(tensor, src=owner_rank) 广播的是 remote_kv_buffer 整个张量 —— 也就是 size + page_size 行全量， 不是本批次命中的那几页。这一点直接决定了 04 节的通信账，也是这条路径最反直觉的地方。

真正让它可用的是一层预取。DeepseekV2DecoderLayer 在做第 l 层注意力之前， 会先把第 l+1 层的广播踢出去（layers/attention/dsa/utils.py:312-328 的 maybe_prefetch_next_full_attention_kv() → prefetch_kv_buffer()，:461-505）：

1
当前 stream 上算第 l 层的注意力 读的是 remote_kv_buffer 里已经就位的那一层
2
kv_broadcast_stream 上同时发起第 l+1 层的广播 prefetch_kv_buffer()：先 wait_stream(current)，再切到专用 stream 做 broadcast
3
第 l+1 层要读时，_finalize_pending_kv_broadcast() 把 pending 提升成 remote_kv_layer_id，并让当前 stream wait_stream 广播流 :450-459；广播与计算重叠，等待只发生在真正需要数据的那一刻

owner rank 自己也走这条路：它的 src_tensor 是自己那份满 buffer， 于是 tensor.copy_(src_tensor) 先拷进 scratch，再作为 broadcast 的 source 参与集合通信 —— 集合通信必须所有 rank 都进，owner 不能缺席，只能多拷一次。

3.5 PD 传输：每个 rank 只报自己那段连续层

prefill 侧算完的 KV 要经 PD 传给 decode。LayerSplit 之后没有任何一个 rank 持有完整 cache， 于是三处语义一起改：

改动原来LayerSplit 下落点
上报哪些层 全部层的 buffer 指针 只报 owned 层（0 行的层天然被跳过） dsa_cache_layer_split.py:362-375
层段标签 start_layer / end_layer layer_shard_start 起，长度 = 上报的指针个数 disaggregation/prefill.py:282-299
谁发 CP 组内只有 rank 0 发（CP 复制状态只发一份） 全 CP rank 都发：cp_sharded_prefill 把 enable_all_cp_ranks_for_transfer 置真 disaggregation/common/conn.py:385-391
CP 复制状态 非 0 号 rank 跳过 不跳过 —— 每个 rank 拥有的是不同的状态层 disaggregation/common/conn.py:513-526
draft cache — 只由最后一个 shard rank 发（draft 不切层，得有人替它发全量） disaggregation/prefill.py:277-279

第 4 行那条注释把话说得很直白："Cache layer split is the exception because each CP rank owns different state layers." —— 这不是优化，是正确性要求：漏发就会让 decode 侧少掉一部分状态层。

05显存 / 通信 / 吞吐 / 延迟：把账算出来

5.1 显存：一个式子，两个加数

per_token_per_layer = (kv_lora_rank + qk_rope_head_dim) × dtype_bytes   # MLA latent
                    + (index_head_dim + index_head_dim/128 × 4)        # DSA index-K + scale，fp8
                    = 576 + 132 = 708 B                                  # fp8 示例

单卡 KV = (ceil(L/S) + 1) × tokens × per_token_per_layer
基线    =  L              × tokens × per_token_per_layer

indexer 那项来自 model_executor/pool_configurator.py:560-571（quant_block_size = 128， memory_pool.py:5280；index_kpool 默认 1）。index-K 用独立的 fp8 buffer，不跟 --kv-cache-dtype 走。

5.2 通信：每次远程层读 = 一整层

因为广播的是整个 remote_kv_buffer（见 3.4），单次远程层读的字节数是 (size + page_size) × per_token_per_layer，与这批请求实际命中多少 page 无关。 一次前向里被读的远程层约 L - ceil(L/S) 层，于是：

每次前向的广播量 ≈ (L - ceil(L/S)) × (size + page_size) × per_token_per_layer

这笔账的量级完全由 size（也就是 max_total_num_tokens）决定 —— 而 LayerSplit 恰好把这个池子撑大了 S 倍。这是它最需要被理解的一处张力： 容量与广播量同向增长。缓解手段是那层预取（把广播塞进计算空档）与 S 不要盲目加大（S 越大，远程层占比越高）。

5.3 吞吐与延迟

维度方向原因
prefill 吞吐↑ 约 ×S同显存下 max_total_num_tokens 涨，能并行的 prefill token 变多
prefill 单层延迟↑ 一点远程层的读要等广播；预取把等待压到一次 stream 同步
prefill 显存↓ 到 (ceil(L/S)+1)/L3.2 的式子
decode 延迟不变LayerSplit 不在 decode worker 上运行，decode 收的是完整分片
PD 传输量不变要传的还是同一份 KV，只是换了发送方：从 1 个 rank 发全量，变成 S 个 rank 各发自己那段

最后一行容易被误解成「传输量变多」。没有：get_contiguous_buf_infos() 报的是 owned 层，S 个 rank 报的是互不相交的层段，加起来正好是原来那一份。 变的是并发度（S 条连接各发 1/S），不是总量。

06它和 TP / PP / DP 到底什么关系

先把最容易混的一处讲掉：SGLang 里「按层切」有两种，帮助文本里都出现过 layer 这个词，但切的东西完全不同。

维度切什么谁持有第 l 层的权重谁持有第 l 层的KV通信原语
TP每层的权重矩阵（按 head / 列切） 全部 rank 各持 1/TP全部 rank 各持一份完整（MLA） all-reduce / all-gather
PP
「model is split by layer」		 计算图按层段切成 stage 只有该 stage 的 rank 持有这段层只有该 stage 的 rank 持有这段层的 KV 点对点 send_tensor_dict
DP请求批次每个副本都完整每个副本都完整（各自装自己的请求） 无（只在负载均衡层）
CP
prefill CP		 一条序列的 token（interleave / zigzag） 每个 CP rank 都完整每个 CP rank 都完整 all-gather（attention 的 KV）
LayerSplit KV/indexer cache 的层归属 不变（仍由 TP 决定） 只有 owner 持有，其余 rank 读 scratch broadcast（owner → CP 组）

一句话概括：TP / PP / DP / CP 是「谁来算」，LayerSplit 是「谁存」。 前四者改变计算图、改变每个 kernel 的形状；LayerSplit 一个 kernel 都不改， 它只是给 kv_buffer 装了一个「按层查表 — 查不到就去 owner 拿」的间接层。

6.1 组合关系

组合能不能说明
× TP必须S = attn_cp_size 嵌在 TP 世界里；推荐拓扑 CP=TP、DP=1，此时 S = TP
× CP寄生没有 CP 就没有 owner 广播的作用域；--enable-prefill-cp 是硬前提
× PP不行pp_size > 1 直接 raise；原文是「CP + PP has not been validated for this feature」
× DP attention受限DSA interleave 的文档口径是「keep DP=1」；e2e 里 DP 只出现在 decode 侧的变体上
× PD必须只有 prefill worker 能开，且必须是 PD 部署 —— 光开 prefill CP 不构成 PD
× EAGLE / MTP并存但不切draft worker 保持完整 cache；门控第一项就是 not is_draft_worker
× EP / MoE A2A正交e2e 的 mixed-MoE 变体在 decode 侧叠了 --ep-size 4 --moe-a2a-backend deepep，prefill 侧不受影响

09常见误解

「LayerSplit 就是 PP 的另一种叫法。」
PP 的帮助文本确实写着 "the model is split by layer"，但那句话描述的是计算图切段： 第 l 层的权重只在一个 stage 上。LayerSplit 不动权重、不动计算图， 它切的是 KV cache 的归属，而且恰恰要求 pp_size == 1。 两者同名不同物，06 节那张表就是为这句话准备的。
「S 越大省得越多，所以往大了开。」
显存确实单调下降（(ceil(L/S)+1)/L），但远程层占比 1 - ceil(L/S)/L 同时在涨， 而每次远程层读要搬一整层。S 从 4 加到 8，显存再多省一点，广播量却接近翻倍。 S 的上界由 tp % (dp × attn_cp_size) == 0 和机器规模决定， 但真正的上限是互连带宽，不是这个整除条件。
「广播只传这批请求命中的那几页 KV。」
不是。_broadcast_tensor_from_owner(self.remote_kv_buffer, …) 广播的是 remote_kv_buffer 整个张量（size + page_size 行）， 与 batch 命中多少 page 无关。这也是为什么「预取一层」不是锦上添花而是必需 —— 否则每个远程层都要在关键路径上等一次全量拷贝。
「decode 侧也能开，反正也是 KV 太大。」
decode 侧开不了，而且是被显式拒绝的（08 节第二条）。 原因不是性能而是语义：非 owner rank 上没有完整 cache，而 decode 的每一步都要全层 KV。 PD 传输把完整分片送到 decode 之后，decode 侧就是普通本地 cache。
「开了 prefill CP 就等于配好了 PD。」
文档专门写了这句："enabling prefill CP alone does not configure a PD deployment"。 LayerSplit 要求的是两者的交集：prefill CP 提供广播作用域，PD 提供「每个 rank 只发自己那段」的传输模型。 只开前者，--disaggregation-mode 那两道门会先把你拦下来。

10自测

Q1 · L = 61, S = 8，每张卡实际持有几层？省了多少？和 cookbook 的「up to 75%」对得上吗？
ceil(61/8) + 1 = 9 层，占 9/61 ≈ 14.8%，省 约 85%。 cookbook 的 75% 是 S = 4 时的渐近值 1 - 1/S（忽略 scratch 那 +1 层）； 同一式子 S = 4 得 (16+1)/61 ≈ 27.9%，省 72.1%。 两个数都对，只是口径不同 —— 引用时务必说清 S 和是否含 scratch。
Q2 · owner rank 自己也读自己那层，为什么还要 copy_ 进 scratch？
因为 comm.broadcast() 是集合通信：所有 rank 都必须进， 包括 source。owner 不能跳过，只能把自己的满 buffer 拷进 scratch 再作为 source 参与。 少进一个 rank 就是死锁，不是「少拷一次」。见 _broadcast_tensor_from_owner() 里 assert src_tensor is not None 之后那段 copy_。
Q3 · 为什么 get_contiguous_buf_infos() 要重写，而 get_kv_size_bytes() 可以直接累加？
因为非 owner 层是 0 行而不是不存在。 get_kv_size_bytes() 遍历 kv_buffer 求和，0 行张量贡献 0 字节，天然正确； 而 get_contiguous_buf_infos() 要把「第几层对应哪个指针」交给 PD 传输， 必须只上报 owned 层再配 layer_shard_start 作为起点 —— 否则对端会把 0 行当成一层。
Q4 · 为什么 draft（MTP / EAGLE）不跟着切？
因为 draft worker 的池子是另一套，而且 is_glm_dsa_cache_layer_split_enabled() 第一项就是 not model_runner.is_draft_worker。draft 层数少、KV 占比低， 切它收益有限却要在 draft 前向里引入一次广播，得不偿失。 对应地，PD 传输侧由最后一个 shard rank 替 draft 发全量 cache （prefill.py:277-280）。
Q5 · LayerSplit 之后，PD 的传输总量会变吗？
不会。S 个 rank 上报的是互不相交的连续层段，并起来正好等于原来那一份。 变的是并发度：从「1 个 rank 发全量」变成「S 个 rank 各发 1/S」。 代价是 CP 复制的状态（线性注意力状态之类）不能再只由 rank 0 发 —— 每个 rank 拥有的是不同的状态层， 见 conn.py:513-526 的注释。
