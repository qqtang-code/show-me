SGLang 并行策略怎样改变 KV 池容量：分子 B 与分母 b

2026-10-21SGLangKV CacheTP / PP / CP / DCP / EP / DPGLM 5.3MLA + DSA

同样 8 张卡，TP8、TP4＋PP2、TP2＋PP4 谁缓存得更多？答案不在"并行度"这个名字里，而在两个数上：每卡还剩多少字节可分给 KV（分子 B），以及一个 token 在这张卡上要占多少字节（分母 b）。单池容量 ≈ B / b。想清楚一条策略动了哪一边，容量变化不用跑实验也算得出来 —— 但只有 PP 同时动两边，这也是 8 卡下它翻倍、而 TP 不翻倍的全部原因。

结论 两个数 分子 B 分母 b TP 与 PP CP DCP EP DP 与 Attention DP 策略矩阵 计算器 常见误解 自测

术语约定：并行维度沿用 SGLang flag 的写法（tp_size / pp_size / attn_cp_size / attn_dcp_size / moe_ep_size / attn_dp_size），不译成"张量维度""流水维度"这类自造词。容量一律指 token 数，不是字节；B 是字节、b 是字节/token，两者混用时以单位区分。

01结论

TL;DR

  • 容量只有一个公式：单池 ≈ B / b。 任何并行策略的容量影响，都能拆成"它动了 B"还是"它动了 b"；两边同时动时，容量倍率 = B 的变化倍率 ÷ b 的变化倍率。
  • TP 只动分子。 权重按 TP 分片释放显存，但普通 MLA 的每个 attention TP rank 仍然保存全部本地层的完整 latent KV —— b 一点没变，收益全部来自 B 变大。
  • PP 同时动两边。 本地层数从 78 变成 39，b 直接减半；而权重份额在 8 卡下没变（1/2 层数 × 1/4 分片仍是 1/8）。容量翻倍的唯一来源是 KV 层数减少，不是权重变少。
  • Attention DP 换的是"重复"。 TP8 时 8 个 attention rank 存同一批请求的同一份 latent；Attention DP8 时 8 个池各存不同请求，唯一 token 容量从约 N 变成约 8N —— 但单条请求仍受单池 N 约束。
  • PP 的多 stage 取最小。 代码对 token_capacity 做 AllReduce(MIN)，所以分层不均衡会直接吃掉整个实例的容量：PP4 的 19–20 层里，决定容量的是 20 层那个 stage。

02先把问题写成两个数

这个问题拆两步：每张卡还剩多少显存分给 KV（分子），一个 token 在这张卡上需要多少缓存（分母）。两个量都是"每卡"口径，所以并行策略只要改变"每卡"的分摊方式，就会改变容量。

单池容量 ≈ B　每卡可分给 KV 的字节b　每个 token 在本卡占的字节
量口径由什么决定主要受哪些策略影响
B字节 / 卡显存总预算减去本地权重、运行时预留、激活、通信缓冲、graph 捕获等工作区TP、PP、EP（分片权重释放 B）；Attention DP、CP（复制权重或放大工作区吃掉 B）
b字节 / token / 卡本地缓存层数 × 每层每 token 成本（主 KV＋index-K）PP（本地层数变少）；CP 的 DSA 层分片；DCP（位置分片）

两者同时变时，别再用"并行度翻倍容量就翻倍"这类线性直觉。容量倍率 = (B 变化倍率) / (b 变化倍率)；协同实例还要再取各 rank 的最小值。

04分母：GLM 5.3 的一个 token 缓存什么

GLM 5.3 的相关配置：78 层、kv_lora_rank=512、qk_rope_head_dim=64、index_head_dim=128，模型类继承 DeepSeek MLA：

这四个数字的来源不一样，别当成同一类事实。「78 层 / 512 / 64」是 checkpoint 的 config.json（num_hidden_layers / kv_lora_rank / qk_rope_head_dim），源码里读不到默认值，只有 kv_cache_configurator.py:2603 的注释 # nope(512 fp8) + rope(64 fp8) 可以佐证；index_head_dim=128 虽然也来自 HF config，但在 memory_pool.py:4924 被 assert index_head_dim == 128 硬断言。反过来，quant_block_size=128 与「RoPE 按 bf16 存 2 字节」都能在代码里直接确认（memory_pool.py:4870、:4872 的 rope_storage_dtype = torch.bfloat16）。

DSA 的 top-k 不减少主 KV。 indexer 选择历史位置，减少的是 attention 的访问与计算量；主 KV 仍然保存完整历史。它能改变的是 index-K 的分配层数（部分层可复用 top-k 结果），而不是把 656 B 压小。

05TP 与 PP：一个切矩阵，一个切层

两者的差别不在"切多少"，而在切的是什么。

TP 切矩阵。 线性层沿输出维／输入维分区，每卡拿到矩阵的一片：

ColumnParallelLinear / RowParallelLinear · layers/linear.py · L360–L365 / L1477–L1481
self.output_size_per_partition = divide(self.output_size, tp_size)   # 列并行
self.input_size_per_partition  = divide(input_size, self.tp_size)    # 行并行

权重分片了，显存释放了，但层数没变：78 层还在，每层仍然要为这批请求保存一份完整 latent。普通 MLA 的每个 attention TP rank 都需要访问这批请求共享的 latent 历史，所以 layer_num 和 kv_cache_dim 都不随 TP 变化。TP 的容量收益全部来自权重分片释放的 B。

PP 切层。 本 stage 之外的所有层都换成 PPMissingLayer 占位：

make_layers · utils/common.py · L1526–L1539 · resolve_layer_indices · layer_setup.py · L153–L154
[PPMissingLayer() for _ in range(start_layer)]
  + [layer_fn(idx=idx) for idx in range(start_layer, end_layer)]
  + [PPMissingLayer() for _ in range(end_layer, num_hidden_layers)]

num_effective_layers = pp_range.end_layer - pp_range.start_layer
num_effective_layers = num_effective_layers * loop_num   # L158–L159

最后那行 × loop_num 是核对源码时补上的：本 stage 的层数在重复循环（loop_num）下会再乘一次。默认 loop_num=1 时它不改变上面的算术，但如果你的模型开了层循环，b 要按乘之后的层数算。

于是 PP 同时改两个数：本地权重重了（分片更大）但层少了，KV 层数也少了。

06CP：计算切分和存储切分是两件事

Prefill CP 把序列位置的计算分给不同 rank，再 gather 回来。要分开看两件事：

① 普通池不省缓存。 普通 MLA／DSA 池在 CP 过程中重建完整 latent 历史，分母仍按本地层数和完整缓存宽度算 —— 和 TP 一样，b 不变。

② 但 CP 会吃掉分子。 因为它挤掉了 attention TP：

derive_attention_widths · runtime_context.py · L73–L78
attn_dp_size = dp_size if enable_dp_attention else 1
return attn_dp_size, tp_size // attn_dp_size // attn_cp_size

Attention DP=1 时：

TP8 ＋ CP1  →  attention TP8
TP4 ＋ CP4  →  attention TP1

第二种配置把注意力投影复制到 4 个 CP rank 上（q_b_proj 等按 attn_tp 分片），每卡权重占用上升，B 下降；激活和通信工作区也一起变。CP 对容量的净影响，是"b 没变、B 变小"的合并结果 —— 方向是不利的，除非打开层分片。

③ DSA 层分片才动分母。 --enable-dsa-cache-layer-split 让每个 CP rank 只保存一部分 KV／index 层，另预留一个远程层 scratch：

07DCP：沿上下文位置分主 KV

DCP 把同一请求的历史位置分给不同 rank：各 rank 对本地分片算部分 attention，再归并。所以它必须区分"本地物理行数"和"整个组的逻辑 token 空间"：

分母侧：目标主 KV 按位置分片，每逻辑 token 的这部分成本缩为原来的 1/c。分子侧：--enable-cp-decode-attn-tp 之类的 Q 投影复制会新增本卡权重，压小 B。B 近似不变时容量接近 c 倍；启用 Q 复制后要看两边降幅谁大。

本页算例不走 DCP。 上面是 v0.5.21 通用 target MLA 的容量映射；GLM 5.3 的 DSA 算例用的是 DCP1。应用时还要匹配模型后端的 token 寻址、KV 收发和 attention 归并路径 —— 公式对不等于这条模型路径实现了它。

08EP：换个方式存专家权重

EP 按专家分配权重，MoE TP 按专家矩阵的中间维分片。两个数乘起来决定本地专家权重：

EP 主要改的是"怎么存"，不是"存多少"。 固定 TP 组宽时 B 近似不变；两者的差别在通信、专家布局、padding 和工作区 —— 这些会进一步改变可用于 KV 的预算，方向不定。要增加 GPU 同时保持 MoE TP，B 才真正变大。

10把所有策略放回同一个公式

每条策略只列一行，单位是"该策略并行度增大时"。统一条件：同一模型、同权重与 KV 精度、同单卡显存预算。

怎么读这张表：① B 增大且 b 相等 → 容量按 B 的倍率增大；② B 相等且 b 减小 → 容量按 1/b 的倍率增大；③ 两边都动 → 用 B 的倍率除以 b 的倍率；④ 协同实例取各 rank 最小值，独立池按各池求和。先判断"这条策略动的是哪一侧"，再谈倍数。

为什么长度按"层数"画。 每层每 token 恒为 788 B，所以层数与字节严格成正比 —— 一条 tick 就是一层， 78 / 39 / 20 可以直接数出来，不必先换算成字节。这也是这份数据里唯一不可再分的诚实单位。

翻倍的来源在长度里，不在权重里。 三种配置的每卡专家权重份额都约 1/8，长度之差全部来自 "每卡还要缓存几层"。这就是"PP 动两侧、TP 只动一侧"的可视版本。

图中的字节是布局算出来的，不是测出来的。若"B 固定"这条假设不成立 （例如 PP 之后通信工作区变大、首尾组件不一致），容量倍数要按 B 的实际变化重算，不能直接照搬 1× / 2× / 3.9×。

容量只是决策的一半。 PP 把层切开之后，stage 之间每次前向都要过一次 ring；PP4 换来 3.9× 容量， 代价落在跨 stage 的通信与气泡上。这一篇只算容量那一半 —— 选配置时另一半点在第 10 节的策略矩阵里（"合计容量"不等于"更好用"）。

并行组会复用同一批卡。 例如 TP4＋PP2＋CP4 用 8 张卡，每个 stage 的 TP4 组同时承担 CP4；Attention DP 和 EP 也各有派生关系。算资源规模时先画出进程和组的对应关系，再代入容量公式。

12常见误解

✗「TP 越大，KV 池越大，因为权重少了」
对一半。权重分片确实释放 B，但普通 MLA 的 b 完全不变 —— 每个 attention TP rank 仍为这批请求保存全部本地层的完整 latent。别指望 TP 能同时压小分母。
✗「PP 只是把权重摊开」
PP 把层摊开，所以连 KV 要缓存的层数一起少了。8 卡下 TP8 → TP4＋PP2 容量翻倍，靠的是把 78 层变成 39 层，而不是权重份额变化（两者都是约 1/8）。
✗「Attention DP 能让单条请求放更多上下文」
不能。它提升的是整机同时承载的唯一 token 数；单条请求仍受它所落那个池的容量约束。问"能放多长"和问"能同时跑多少"是两个问题。
✗「DSA 用 top-k 选历史，所以 KV 变小了」
top-k 减少的是 attention 的访问与计算量，主 KV 仍保存完整历史。index-K 有自己的 132 B／层／token，而且它只在部分层分配时才省。

13自测：能答上这五题就算懂了

1. 8 卡、78 层，TP8＋PP1 换成 TP4＋PP2，容量为什么约翻倍？权重份额变了吗？

没变。两种配置的每卡路由专家权重份额都约 1/8（1 层数比 × 分片比）。翻倍来自 b 减半：每卡保存的 KV 层数从 78 降到 39。B 近似不变，容量 ≈ B/b 翻倍。

2. 把 TP 从 4 调到 8，普通 MLA 的 b 会变吗？为什么？

不会。普通 MLA 的每个 attention TP rank 都要访问这批请求共享的 latent 历史，layer_num 和 kv_cache_dim 都不随 TP 变。TP 的收益全部来自权重分片释放的 B。

3. TP2＋PP4 的理论容量写了 3.9 倍，为什么不是 4 倍？

78 层分成 4 个 stage 不是整数：19–20 层。决定容量的是最重的那一个 stage（20 层），所以是 78/20 = 3.9，而不是 78/19.5 = 4。代码对 token_capacity 做 AllReduce(MIN)，最穷的 stage 说了算。

4. 开了 DSA 层分片，78 层 CP4，为什么主缓存按 21 层算而不是 20 层？

ceil(78/4) = 20 个所属层，再加 1 个远程层 scratch。get_glm_dsa_layer_split_effective_num_layers 返回 max(1, owned + 1)，scratch 层计入同一个分母。

5. EP 从 1 调到 8（固定 TP 组宽），每卡专家权重会变小吗？

不会。固定 TP 总组宽且 MoE_DP=1 时有 MoE_TP = TP / EP，所以 EP × MoE_TP = TP 恒定，本地路由专家权重 ≈ 本 stage 权重 / TP 不变。EP 换的是"怎么存"，差别在通信、专家布局和 padding。
