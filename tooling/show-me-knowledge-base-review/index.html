小节级

搜索能落到正文位置

搜索不是只扫标题；它能返回小节标题、上下文片段并深链到锚点，这个方向正确。

单文件

不要急于换技术栈

文章自包含、离线可读、便于直接分享。18 篇规模下，没有引入 React、搜索服务或双主题的必要。

源码锚点、证据类型、真实数字、常见误解和自测也构成了内容辨识度。调整应减少选择成本，而不是把这些特点磨平。

02P0：先修发布契约与失效锚点

一句话：这些问题会让读者点不到目标，或让公开仓库的实际状态与自身规则不一致。

问题证据建议
分类链接锚点失效shell.py: _bar() 生成 index.html#inference-systems；门户分类区块实际为 id="cat-inference-systems"。静态审计共发现 23 处。统一为 #cat-<category>；同时让链接检查解析 #fragment 并验证目标页面存在对应 id。
发布状态含义冲突线上可访问的条目中有 5 篇写 visibility: internal；全库同时使用 public、public-ok、internal 三种值。明确它表示“当前页面可否公开”还是“原始材料敏感度”。前者应只构建 public-ok；后者应改名并另设 publish 状态，不能直接批量翻值。
脱敏约定未覆盖元数据4 份线上 meta.json 的 cwd 保留本机绝对路径，与 README 的公开仓库约定冲突。公开构建清空或拒绝绝对路径；同时检查完整 session id、内部 URL、主机名与 IP。审查报告不复述这些值。
同步脚本允许带病发布sync.sh 对坏链接只告警；push 失败也返回 0。链接或快速验收失败时不提交；push 失败返回非零。把“命令执行过”与“线上发布成功”分开。
最小验收：修复后，片段链接审计应为 0；公开构建不得包含 internal 或绝对路径；人为制造一个坏锚点时，sync.sh 必须失败且不能提交。

03P1：搜索从“匹配很多”变成“最相关在前”

一句话：保留现有的小节级索引，只改 normalize、score 和结果分组即可，不必引入搜索服务。

查询当前结果数暴露的问题
TP44纯 substring 匹配，短缩写可命中其他英文单词内部。
SGLang39结果按分类与日期排列，不按相关度；每篇还可追加两个小节。
KV32缺少默认结果上限，常见主题需要长距离扫读。

04P1：首页面向读者，卡片只保留决策信息

一句话：首屏先回答“适合谁、能解决什么、证据可靠到什么程度”，文件组织方式留给 README。

1
改 hero 文案。当前 index.html / notes.md / meta.json 是维护者视角。可换成“面向推理与多卡通信实践者；每篇给出结论、机制、数字依据与适用边界”。
2
缩短 one_liner。当前平均 262 字符，9/18 超过 240。建议正文用“读者问题 + 一个核心结论 + 一个关键数字”，其余细节留在文章 lead。
3
避免承诺固定模板。门户写“每篇都按速览 → 机制 → 实测 → 常见误解 → 自测”，实际并非每篇都有所有模块。改成“常见结构”，不要为一致而补空节。
4
明确 notes 的定位。目前 8/18 篇有 notes.md。若它是可选纯文字备份，文案写“部分条目附 notes”；若它承担无障碍或归档职责，再补齐并做一致性检查。

摘要不一定要更短到失去信息，而是不要在卡片里塞进整段推导。卡片负责帮助选择，文章负责完整论证。

05P1：治理标签、路线和“已打开”状态

标签：从自由累加改为受控词表

95 个标签中 75 个只出现一次，意味着多数标签不能形成有效分组。保留具体术语在正文可搜索即可；标签优先承担跨文章聚合。先合并大小写、连字符和中英文别名，再把配置值、一次性模型名、单个公式从标签中移出。

阅读路线：区分 path 与 collection

三条路线共覆盖 12/18 篇，最近增加的 6 篇都未进入路线。不是每篇都必须进路线，但需要一个小型“最近更新”入口，否则非首分类的新文章会沉下去。

“源码走读与实践”目前更像同方法合集，torchrun 并不是 MoE 通信或 DFlash 的前置。建议给它标记 kind: collection，取消“前一篇是后一篇前置”的承诺；真正 path 才显示严格先后关系。

已打开：在文章页记录，而不是只在卡片上记录

当前唯一写入 showme:opened 的位置是门户卡片点击监听。推荐路线、搜索结果、上一篇/下一篇和直接 URL 都不会更新。最小修法是在文章 shell 初始化时写入当前 dir，门户继续只负责展示。

06建议的调整顺序与验收

级别做什么完成判据
P0统一分类锚点；明确 visibility；清理公开元数据；让同步失败可阻断。0 个坏片段；公开构建无 internal / 绝对路径；故障注入会阻止提交。
P1搜索排序、词边界、别名与按文章分组；补固定查询回归。AllReduce、all-reduce、TP、KV 四组验收通过，首屏结果可直接选择。
P1缩短卡片摘要；hero 改为读者视角；标签归一；路线区分合集；文章页记录打开状态。卡片可快速比较；路线描述与实际依赖一致；四种进入方式都更新进度。
P2为源码型文章增加 applies_to / verified_at；内容继续增长后再拆分搜索索引。读者能区分写作日期、源码版本与最近核对日期；50+ 篇时再评估懒加载。
不建议现在做：全面换肤、React/Vite 重构、深色模式、服务端搜索、为了分类齐全而拆出空分类。这些都不解决当前最影响使用的问题。
这份审查没有断言什么？
没有断言各篇文章的技术结论正确或错误，也没有把 internal 直接等同于“正文未脱敏”。发布项指出的是状态语义和公开元数据的一致性问题，需要由维护者确认原始材料与发布意图后再调整。
为什么不建议马上拆搜索索引？
当前门户约 594 KiB、gzip 后约 236 KiB，已经值得观察，但 18 篇下仍能工作，而且内联索引满足本地直接打开与离线搜索。等条目继续增长、首屏成本成为实际测量问题后，再做按需加载更合适。
