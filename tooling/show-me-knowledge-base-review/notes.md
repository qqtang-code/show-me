# show-me 知识库体检：改了什么，以及为什么这么改

日期：2026-11-16  
范围：线上门户、19 份 `meta.json`、文章外壳、搜索与构建脚本。数字来自本地复算、headless Chrome 与 `verify_site.py`；未逐条核验各文章的技术结论。

## TL;DR

不需要重做视觉或技术栈。问题集中在发布契约、检索排序和状态语义上——而且其中一项功能从来没真正生效过。

- 改动后完整验收 **70 PASS / 0 FAIL / 1 SKIP**，六档宽度无整页横向溢出。
- **23 处分类锚点**指向不存在的 id；旧链接检查只判断文件存在，锚点写错照样全绿。
- **标签筛选从来没生效**：`.card{display:flex}` 盖掉了 `[hidden]` 的 `display:none`，点标签前后都是 19 张卡片。
- 搜索没有相关度排序、没有词边界；`TP` 复算 44 处，`all-reduce` 与 `AllReduce` 是两组结果。
- `visibility` 一个字段同时承担「原料多敏感」和「能不能公开」，5 篇公开页面上写着 `internal`。
- `one_liner` 平均 262 字符、最长 475，同一行两张卡无法横向比较。

## 01 保留下来的基础

1. **自动化验收基础良好。** 改动后 `verify_site.py` 仍是 70 PASS、0 FAIL、1 个桌面限定 SKIP。
2. **搜索的粒度本来就对。** 小节级索引 + 片段 + 锚点深链都保留，这一轮只换排序与呈现。
3. **没换技术栈。** 文章自包含、离线可读、可单独发出；19 篇规模下引入 React 或搜索服务只会增加故障面。

## 02 发布契约：让检查器真的能拦住问题

| 问题 | 处理 | 验证 |
|---|---|---|
| 分类锚点失效 | `shell.py` 与正文手写面包屑统一改为 `index.html#cat-<category>`；`check_links.py` 解析 `#fragment` 并与目标页 `id` 集合比对。 | 先在 23 处上失败，修完 20 个页面 0 失效。 |
| 发布语义混用一个字段 | 拆成 `visibility`（原料敏感度）与 `publish`（是否批准公开）；`publish:false` 不进门户 / README / 上一篇下一篇；旧 `public-ok` 归一到 `public`。 | 5 篇 `internal` 保留原料标记、`publish:true` 明确公开。 |
| 脱敏没覆盖元数据 | 构建期把 `cwd` 绝对路径改写为仓库相对路径；其余字段仍有本机绝对路径或完整 session id 时中止构建（不打印原值）。 | 4 份被自动改写，公开元数据 0 条绝对路径。 |
| 同步允许带病发布 | `sync.sh` 链接检查失败即中止且不提交；push 失败返回非零。 | 故障注入：坏锚点阻止提交。 |

**判断留给你：** `visibility: internal` 不等于「正文没脱敏」，所以没有批量下线这 5 篇。现读法是「原料来自内部，已脱敏并批准公开」；若某篇不该公开，把 `publish` 改成 `false` 即可。

## 04 首页与卡片

1. **hero 改成读者视角。** 首屏原来在讲目录结构（维护者视角），已移到页脚；改成「写给做推理与多卡部署的实践者」。
2. **去掉没兑现的模板承诺。** 「每篇都按速览 → 机制 → 实测 → 常见误解 → 自测」改为「常见结构，具体小节以页面为准」。
3. **压缩卡片摘要。** `one_liner` 平均 262 → 186 字符，最长 475 → 234，超过 240 的从 9 篇降到 0 篇，关键数字一个没删。
4. **加「最近更新」，并让漏收录自己冒出来。** 审查时路线只覆盖 12/18 篇，且 `curation.json` 自 2026-10-21 起没再改过——之后发布的 6 篇一篇都没被考虑。现在覆盖 17/19，构建期还会对「既不在 `routes` 也没登记进 `unlisted`」的条目告警。

## 05 标签、路线与「已打开」

**标签**：新增 `taxonomy.json`，构建期归并同义写法，各篇 `meta.json` 保留原词。唯一标签 95 → 92，单例 75 → 69；`AllReduce` 3 → 5 篇，`DSA`、`GLM 系列` 同样收敛。代价：`GLM-5.3` 这类具体写法不再各自占一个标签位，但仍留在 `meta.json` 与正文里。

**路线**：`curation.json` 增加 `kind`——`path` 表示前一篇是后一篇的前置，`collection` 表示同方法合集、可挑读。门户显示「路线 · N 篇」/「合集 · N 篇」。

补成员时发现「多卡通信」一条塞不下（`DESIGN.md` 约定每条 3–5 篇），按问题拆成两条：**集合通信怎么省时间**（原语 → 少搬字节 → 砍固定开销 → 藏进计算 → MoE 的 A2A 内核）与**并行切分与跨机通信**（CP 换算子 → EP 改权重排布 → TP16 跨机分层）。`stream-interval` 移入「源码走读与实践」。

清单改为对象形态：`routes` 之外新增 `unlisted`，显式登记「确认不进路线」的两篇（横向对比、站点自身体检页），否则告警会一直响。

**已打开**：原来唯一写入点 `showme:opened` 是门户卡片点击监听，从路线、搜索、翻页、外链进入都不记录。现在文章页 shell 按 `<cat>/<slug>/` 自己落盘，门户只负责展示，并按 `data-dir` 统一监听路线与最近更新的链接。

## 06 挖出来的真 bug：标签筛选从未生效

```text
实测（headless，修复前）
  隐藏 2 张卡片后可见卡片数   19 → 19      ← hidden 没起作用
  点 SGLang 标签后可见卡片数   19 → 17      ← 只隐藏空分类，同分类内不匹配的仍在
修复 [hidden]{display:none!important} 后
  隐藏 2 张卡片后可见卡片数   19 → 17
  点 SGLang 标签后可见卡片数   19 → 11      ← SGLang 确实对应 11 篇
```

原因：`.card{display:flex}` 是作者样式，会盖掉 UA 样式表里 `[hidden]{display:none}`。原探针没抓到，是因为它只检查 computed display，而分类页签恰好靠隐藏 `.cat` 容器生效，看起来「筛选能用」。

教训：交互验收要断言「数量确实变少且等于预期」，而不是「数量变了」。类别筛选与标签筛选看似同一功能，实际一条走容器、一条走卡片，坏的只是后者。

## 07 还没做的

| 级别 | 事项 | 判断 |
|---|---|---|
| P2 | 源码型文章加 `applies_to` / `verified_at` | 有价值但要逐篇回填，先定「版本对齐粒度」，等下次内容更新顺带补。 |
| P2 | 拆内联搜索索引、按需加载 | 门户约 600 KiB / gzip 约 240 KiB，19 篇仍可接受，且内联才能离线搜。 |
| P2 | 已读进度是否也在文章列表高亮 | 路线与最近更新不是卡片结构，需要另一套样式，收益不明显。 |

明确没做：换肤、深色模式、React/Vite 重构、服务端搜索、为分类齐全而拆空分类。

## 边界

- 未断言各篇文章的技术结论正确或错误。
- 未把 `internal` 等同于「正文该不该公开」；只把两个含义拆成两个字段，让判断可表达。
- 锚点问题之前全绿，是因为链接检查丢掉了 `#` 之后的部分，读者点过去不 404、只停在页首。
