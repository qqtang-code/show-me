# show-me 知识库体检：先修发布契约，再优化检索与导览

日期：2026-11-16  
范围：线上门户、18 份 `meta.json`、文章外壳、搜索代码与构建验收脚本。数字来自本地复算和 headless Chrome；未逐条核验各文章的技术结论。

## TL;DR

总体不需要重做视觉或技术栈。现有视觉、移动端和单文件架构已经稳；下一轮应集中修发布可靠性、搜索有效性和内容可扫读性。

- 完整验收 **0 FAIL**（18 篇状态 67 项 PASS，加入本篇后 70 项），六档宽度均未发现整页横向溢出。
- **23 处分类片段链接**指向不存在的锚点；**5 篇公开页面**仍标 `internal`，**4 份公开元数据**仍含本机绝对路径。
- 搜索缺少相关度排序与短标识符词边界；`TP` 按当前算法复算出 44 处结果。
- `one_liner` 为 119–475 字符，平均 262，更像完整 abstract，不利于卡片扫读。
- 18 篇已有 95 个标签，其中 75 个只出现一次，并存在 `AllReduce / allreduce / all-reduce` 分裂。
- 阅读路线覆盖 12/18 篇；“已打开”只记录门户卡片点击，从推荐路线、搜索结果或直达文章进入均不记录。

## 01 现有基础：应该保留

1. **自动化验收基础良好。** `verify_site.py` 已覆盖结构、链接路径、六档布局、门户交互与 shell 幂等。
2. **小节级搜索方向正确。** 能返回小节标题、上下文片段并深链到锚点。
3. **单文件架构仍有价值。** 文章自包含、离线可读、便于直接分享。18 篇规模下，没有引入 React、搜索服务或双主题的必要。
4. 源码锚点、证据类型、真实数字、常见误解和自测构成内容辨识度，不应为统一模板而磨平。

## 02 P0：发布契约与失效锚点

| 问题 | 证据 | 建议 |
|---|---|---|
| 分类链接锚点失效 | `shell.py: _bar()` 生成 `index.html#inference-systems`；门户实际为 `id="cat-inference-systems"`。静态审计共 23 处。 | 统一为 `#cat-<category>`；链接检查同时验证 fragment 对应 id。 |
| 发布状态含义冲突 | 线上可访问条目有 5 篇写 `visibility: internal`；全库混用 `public`、`public-ok`、`internal`。 | 明确是当前发布许可还是原始材料敏感度。前者只构建 `public-ok`；后者改名并另设 `publish`，不要直接批量翻值。 |
| 脱敏未覆盖元数据 | 4 份线上 `meta.json` 的 `cwd` 保留本机绝对路径。 | 公开构建清空或拒绝绝对路径，并检查完整 session id、内部 URL、主机名与 IP。 |
| 同步允许带病发布 | `sync.sh` 对坏链接只告警，push 失败也返回 0。 | 链接或快速验收失败时不提交；push 失败返回非零。 |

最小验收：片段链接审计为 0；公开构建不含 `internal` 或绝对路径；人为制造坏锚点时 `sync.sh` 失败且不提交。

## 03 P1：搜索从“匹配很多”变成“最相关在前”

保留小节级索引，只改 normalize、score 和结果分组，不必引入搜索服务。

按当前 JavaScript 搜索算法对同一份构建数据复算：

| 查询 | 当前结果数 | 暴露的问题 |
|---|---:|---|
| `TP` | 44 | 纯 substring 匹配，短缩写可命中其他英文单词内部。 |
| `SGLang` | 39 | 结果按分类与日期排列，不按相关度；每篇可追加两个小节。 |
| `KV` | 32 | 缺少默认结果上限，常见主题需要长距离扫读。 |
| `AllReduce` | 25 | 同名文章不一定靠前；`all-reduce` 得到不同结果集。 |

建议：

```text
normalize
  lowercase
  unify allreduce / all-reduce / all_reduce through aliases
  match short ASCII identifiers on token boundaries

rank
  exact title match > title token > tag > section heading > body

present
  one article + its best section
  expand more sections on demand
  show the first 10–20 articles, not every matching section
```

固定回归查询：`AllReduce` 同名文章进入前三；`TP` 不因其他单词包含这两个字母而命中；`all-reduce` 与 `AllReduce` 返回同一组核心结果。

## 04 P1：首页面向读者，卡片只保留决策信息

1. **改 hero 文案。** 当前 `index.html / notes.md / meta.json` 是维护者视角，移到 README；首屏改为“适合谁、解决什么、证据可靠到什么程度”。
2. **缩短 `one_liner`。** 当前平均 262 字符，9/18 超过 240。卡片保留“读者问题 + 一个核心结论 + 一个关键数字”，其余细节留在文章 lead。
3. **避免承诺固定模板。** 门户写“每篇都按速览 → 机制 → 实测 → 常见误解 → 自测”，实际并非每篇都有所有模块。改成“常见结构”，不要为一致而补空节。
4. **明确 notes 定位。** 目前 8/18 篇有 `notes.md`。可选备份就写“部分条目附 notes”；若承担无障碍或归档职责，再补齐并做一致性检查。

卡片负责帮助选择，文章负责完整论证。

## 05 P1：标签、路线和“已打开”状态

### 标签

95 个标签中 75 个只出现一次，多数不能形成有效分组。具体术语保留在正文可搜索即可；标签优先承担跨文章聚合。先合并大小写、连字符和中英文别名，再移出配置值、一次性模型名与单个公式。

### 阅读路线

三条路线覆盖 12/18 篇，最近增加的 6 篇都未进入路线。不是每篇都必须进路线，但可增加小型“最近更新”入口，避免非首分类的新文章下沉。

“源码走读与实践”更像同方法合集，`torchrun` 不是 MoE 通信或 DFlash 的前置。建议标记 `kind: collection`，取消严格前置承诺；真正 path 才显示先后关系。

### 已打开

当前唯一写入 `showme:opened` 的位置是门户卡片点击监听。推荐路线、搜索结果、上一篇/下一篇和直接 URL 都不会更新。最小修法是在文章 shell 初始化时写入当前 `dir`，门户继续只负责展示。

## 06 调整顺序与验收

| 优先级 | 做什么 | 完成判据 |
|---|---|---|
| P0 | 统一分类锚点；明确 visibility；清理公开元数据；让同步失败可阻断。 | 0 个坏片段；公开构建无 internal / 绝对路径；故障注入阻止提交。 |
| P1 | 搜索排序、词边界、别名与按文章分组；补固定查询回归。 | AllReduce、all-reduce、TP、KV 四组验收通过。 |
| P1 | 缩短摘要；hero 改为读者视角；标签归一；路线区分合集；文章页记录打开状态。 | 卡片可快速比较；路线描述与依赖一致；四种进入方式都更新进度。 |
| P2 | 为源码型文章增加 `applies_to` / `verified_at`；内容增长后再拆搜索索引。 | 读者能区分写作日期、源码版本与最近核对日期；50+ 篇时再评估懒加载。 |

**暂不建议：**全面换肤、React/Vite 重构、深色模式、服务端搜索、为分类齐全而拆空分类。

## 边界

- 未断言各篇技术结论正确或错误。
- 未把 `internal` 直接等同于“正文未脱敏”；发布项指出状态语义和公开元数据的一致性问题。
- 当前门户约 594 KiB、gzip 后约 236 KiB，值得观察，但 18 篇下仍能工作且满足离线搜索；等内容增长、首屏成本成为实测问题后再按需加载。
